# Installed service versions

The dialog owns its open state. ServiceManager binds the established module's installed versions and persisted current version. ModuleInstalledItem owns start, stop, and restart through the terminal reply, including progress and the existing duplicate guard. Starting a different version for an exclusive service uses the module's existing version switch and the same companion service hooks. The fork owns the running processes and ports.

The module owns discovery and ServiceActionStore owns PATH, aliases, and managed version deletion. These paths retain their existing stores and persisted settings. The dialog adds no operation state, IPC, or persistence. Test opening the dialog for a discovered service, starting a second version, closing and reopening during progress, and observing the current version after completion.

Runtimes bind the non-service version table. Its open state belongs to the screen. Module owns discovery from open, refresh and custom folder changes through the per-module result or timeout. Concurrent callers share the discovery request and its cleanup. ServiceActionStore owns PATH from the selected row to the terminal reply, status, notice and listener cleanup. It guards duplicate writes for the same binary. The runtime summary reads discovered versions and the app-managed PATH from their existing owners. PATH discovery supplements the runtime scan, so an unavailable PATH query leaves installed versions visible. Discovery failure for one runtime does not stop other rows. There are no child processes or companion services to start or stop, and the dialog adds no new persistence or state store.

Verify the Python entry with two discovered versions. Close and reopen during a PATH write, then check the selected version in the summary once the reply arrives. Add a custom discovery folder and verify the rescan and displayed version list.
